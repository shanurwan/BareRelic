# BareRelic working rules

BareRelic is a read-only data recovery and forensic reconstruction tool.
Read `docs/architecture.md` and `docs/forensic-principles.md` first.

- Preserve user edits. Do not commit or push.
- Never write to a source, and never run commands against real devices
  (`/dev/sd*`, `\\.\PhysicalDrive*`, `/dev/rdisk*`) — use images generated by
  `internal/testutil` or `make demo`.
- Standard library only. Every parser of on-disk data bounds its allocations
  by bytes that exist, guards pointer-following loops, and has a fuzz target.
- File-system code plans (extents + confidence + notes); only `internal/cli`
  reads bytes into an `evidence.Case`.
- Confidence and notes must state every assumption. Keep validation
  boundaries in the docs honest: synthetic-image tests do not demonstrate
  behaviour on real media or real failing hardware.
- Never commit disk images, rescue maps or case output.

Build/test: `go test ./...`, `go vet ./...`, `gofmt -l .`;
`CGO_ENABLED=0 go build ./cmd/barerelic`. Race tests need a C compiler:
`go test -race ./...`. Fuzz: `make fuzz`.
